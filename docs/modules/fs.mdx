### What is the file system module?

`fs` is a small wrapper over the native file manager. Use it to read, write, remove, and check files. By default, every path resolves against the platform's **documents directory** (the private, persistent folder where Unbound stores its data), so you can use short relative paths instead of absolute ones.

`fs` is built on the [native](/modules/native) bridge. [i18n](/modules/i18n) loads its string tables through it.

```ts
import { fs } from '@unbound-app/api';
// equivalent: import * as fs from '@unbound-app/api/fs';
// runtime global: unbound.fs

await fs.writeFile('my-plugin/data.json', JSON.stringify({ count: 1 }));
const raw = await fs.readFile('my-plugin/data.json');
```

### Reading & writing

`readFile` and `writeFile` default to `utf8` encoding. `readFile` resolves to the file's contents, and `writeFile` resolves once the file is on disk. If you need the absolute documents path, it's in `fs.documentsPath`.

<CodeGroup>
```ts writeFile
import { fs } from '@unbound-app/api';

await fs.writeFile('my-plugin/notes.txt', 'hello');

````

```ts readFile
const contents = await fs.readFile('my-plugin/notes.txt');
// contents === 'hello'
````

```ts base64
// Pass an encoding when you're not working with text.
await fs.writeFile('my-plugin/icon.png', base64Data, 'base64');
```

</CodeGroup>

<Note>
	Relative paths resolve against `fs.documentsPath`. To read a file elsewhere on disk, pass an
	absolute path and `false` as the `inDocuments` argument: `fs.readFile('/abs/path', 'utf8',
	false)`.
</Note>

### Checking & removing

`exists` checks whether a file exists, and `removeFile` deletes it. Both resolve to a boolean.

```ts
import { fs } from '@unbound-app/api';

if (await fs.exists('my-plugin/data.json')) {
	await fs.removeFile('my-plugin/data.json');
}
```

<Tip>
	For configuration, use [storage](/modules/storage) instead. Use `fs` directly when an addon
	ships its own data files, such as caches, exports, or downloaded assets, that don't belong in a
	settings Bucket.
</Tip>
