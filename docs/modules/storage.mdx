### What is Storage?

`storage` holds your addon's settings. Values you write are held in memory, broadcast as a change, and saved to disk, so your addon's configuration survives a reload without any file handling on your part.

Writes are debounced and handed to the loader, which saves them to `Unbound/settings.json` in the documents directory. You don't read or write that file yourself.

```ts
import { storage } from '@unbound-app/api';
// equivalent: import * as storage from '@unbound-app/api/storage';
// runtime global: unbound.storage

const settings = storage.getBucket();

settings.set('enabled', true);
settings.get('enabled', false); // → true
```

### Buckets & keys

A setting is one key and its value. Settings are grouped into **Buckets**: named groups saved under their name.

In a plugin, `storage.getBucket()` with no name returns your plugin's own Bucket, named after its `id`. Pass a name to read another Bucket. Outside a plugin, the name is required.

Keys inside a Bucket are dot-paths. `set('appearance.compact', true)` writes `{ appearance: { compact: true } }` and creates the intermediate objects for you.

```ts
import { storage } from '@unbound-app/api';

const settings = storage.getBucket();
settings.set('appearance.compact', true); // dot-path key
settings.get('appearance.compact', false); // with a default
```

### Reading & writing

Every read takes a default value, which is returned when the key isn't set yet. This means `get` never returns an unexpected `undefined`.

<CodeGroup>
```ts get & set
const settings = storage.getBucket();

settings.set('volume', 0.8);
const volume = settings.get('volume', 1); // default 1 if unset

````

```ts toggle
// Flip a boolean against its current (or default) value.
settings.toggle('muted', false);
````

```ts remove & clear
settings.remove('volume'); // delete one key
settings.clear(); // drop the whole Bucket
```

</CodeGroup>

<Note>
	`get` requires a default as its last argument. This keeps the Bucket predictable and keeps
	`undefined` out of your UI.
</Note>

### Reactivity

In React, `storage.useBucket(name)` returns a Bucket and re-renders the component whenever that Bucket changes. Pass an optional predicate to narrow _which_ changes trigger a re-render.

```tsx
import { storage } from '@unbound-app/api';

// Re-renders the component whenever this Bucket changes.
function Toggle() {
	const settings = storage.useBucket('my-plugin');
	const compact = settings.get('appearance.compact', false);

	return <Switch value={compact} onValueChange={(v) => settings.set('appearance.compact', v)} />;
}
```

Outside React, `storage.onChange(predicate, callback)` runs `callback` for each change that `predicate` accepts. The payload names the Bucket in `store` and the key in `key`. `onChange` returns a function that removes the listener. In a plugin, the listener is also removed when the plugin stops.

```ts
import { storage } from '@unbound-app/api';

storage.onChange(
	({ store, key }) => store === 'my-plugin' && key === 'volume',
	({ value }) => logger.log('Volume is now', value),
);
```

`storage.persist()` saves pending changes right away instead of waiting for the debounce.
