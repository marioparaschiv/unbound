A plugin with images adds `assets/`; an addon page with a banner adds `media/`. Git ignores `dist/` and `node_modules/`. [Project Rules](/docs/developer/getting-started/project-rules) lists the layout rules.

## Root Files

### manifest.json

`main` names the entry inside `src/`. `icon` names one of Discord's icons. See [The Manifest](/docs/developer/publishing/manifest).

```json manifest.json quoted
{
	"id": "unbound.character-counter",
	"name": "Character Counter",
	"description": "Shows the current message length and Discord's character limit in the composer.",
	"authors": [
		{
			"name": "thororen",
			"id": "848339671629299742"
		},
		{
			"name": "creations",
			"id": "209830981060788225"
		},
		{
			"name": "adrian",
			"id": "224617799434108928"
		}
	],
	"version": "1.0.4",
	"icon": "TextIcon",
	"main": "index.tsx"
}
```

Never write `platforms` or Capabilities. `ubd build` derives them and fails if you add them by hand.

### Build Config

`unbound` reads the manifest, bundles `src/`, generates the settings and i18n modules, and runs the build checks.

```js rollup.config.mjs quoted
import { unbound } from '@unbound-app/cli/rollup';

export default unbound(import.meta.url);
```

| File | Holds |
| --- | --- |
| `package.json` | `"type": "module"`, `build` and `test` scripts. `devDependencies`: `@unbound-app/api`, `@types/react`, `react-native`, `@unbound-app/cli`. First-party plugins also depend on `@unbound-plugins/shared`; third-party plugins write those helpers themselves |
| `tsconfig.json` | `types: ["bun", "@unbound-app/api/global"]` for the scope globals such as `logger` and `addon`. Maps `~/*` to `./src/*`, which the build also resolves. Extends the workspace `../tsconfig.json` and includes `src`, `tests` and `settings.ts` |
| `bunfig.toml` | Preloads the testing preset, which stands in for Unbound, Discord and the build. See [Writing Tests](/docs/developer/testing/writing-tests) |

```toml bunfig.toml quoted
[test]
# Serves the plugin's manifest, translations, settings and a fake Unbound API to every test.
preload = ["@unbound-app/api/testing/preset"]
```

## The Entry

`src/index.tsx` starts features and holds no logic.

```tsx src/index.tsx quoted
import { runFeatures } from '@unbound-plugins/shared/lifecycle/features';

import { startCounter } from '~/counter';

export const { start, stop, selfTest } = runFeatures([startCounter]);
```

`stop` has nothing to undo here: the Addon scope removes the patch. See [Lifecycle](/docs/developer/getting-started/lifecycle#what-stop-must-undo) for what still needs one.

`selfTest` runs after a restart in the device matrix and returns `{ ok, detail }`. A plugin whose features all skipped still passes `start`; the self-test fails it. `runFeatures` from `@unbound-plugins/shared/lifecycle/features` builds all three exports: `selfTest` reports `ok` while the started features run, and says why when one failed, skipped or still waits for a module Discord has not loaded.

`runFeatures` takes start functions that may return a cleanup, or a function of the start context that returns them. `stop` runs every cleanup in reverse. Logs go through the Addon scope's `logger`, so they carry the plugin's name.

| Option | When a feature throws | Use when |
| --- | --- | --- |
| none | Logs and records a failure. Others still start | Features are independent (usual) |
| `atomic: true` | Removes features already started and records a failure | Features need each other |

## A Feature

Each feature lives in its own folder under `src/` and starts itself. Character Counter has one, `src/counter/`.

### index.tsx

Makes the patch. The JSDoc names what it patches and reads.

```tsx src/counter/index.tsx quoted
import ensureModules from '@unbound-plugins/shared/metro/ensure-modules';
import { cloneElement, isValidElement, type ReactNode } from 'react';
import { patcher } from '@unbound-app/api';

import { ChatInputs, FloatingChatInputContainer, SelectedChannelStore } from '~/counter/modules';
import { CharacterCounter } from '~/counter/components/character-counter';

type ContainerProps = { channel?: { id?: string }; channelId?: string };

/**
 * @description Shows the counter above the composer without changing the composer's layout.
 * Patches the render of `FloatingChatInputContainer`, reads the draft from `ChatInputs`, and the
 * Nitro tier from `UserStore`. The Addon scope removes the patch when the plugin stops.
 */
export function startCounter(): void {
	if (!ensureModules({ ChatInputs, FloatingChatInputContainer })) return;

	patcher.react.after(FloatingChatInputContainer, 'default', ({ props, result }) => {
		const container: ContainerProps = props;
		const channelId =
			container.channel?.id ?? container.channelId ?? SelectedChannelStore.getChannelId();

		if (!channelId || !isValidElement<{ children?: ReactNode }>(result)) return;

		return cloneElement(
			result,
			{},
			<>
				{result.props.children}
				<CharacterCounter key='character-counter' channelId={channelId} />
			</>,
		);
	});
}
```

| Habit | Why |
| --- | --- |
| `ensureModules` | Logs one line, fails the self-test and returns `false` if a module is missing, so only this feature skips. Never loads a lazy handle; until Discord loads one, the self-test reports it as waiting |
| Patch `'default'` on the module | Reading the component itself would load the module at start |
| Add a child, keep `children` | Other plugins may patch the same component |

### modules.ts

Every handle to something outside the plugin. When Discord renames a module, the fix is one line here.

```ts src/counter/modules.ts quoted
import { flux, metro } from '@unbound-app/api';

export const ChatInputs = metro.findByProps('getBestActiveInputForChannelId');
export const FloatingChatInputContainer = metro.findByFilePath(
	'modules/chat_input/native/FloatingChatInputContainer.tsx',
);

export const SelectedChannelStore = flux.getStore('SelectedChannel');
export const ChannelStore = flux.getStore('Channel');
export const UserStore = flux.getStore('User');
```

All lazy, so this file costs nothing at launch. `flux.getStore` is typed. Prefer `metro.api`, `metro.common` and `metro.stores` when they hold what you need; the component reads `metro.common.Theme`. See [Finding Modules](/docs/developer/plugins/metro#modules-unbound-already-found).

### limit.ts

Decision logic goes in plain files with no API imports, so tests reach it directly. `colors.ts` does the same for theme colors.

```ts src/counter/limit.ts quoted
import type { FluxUser } from '@unbound-app/api/flux';

export type CounterTone = 'primary' | 'muted' | 'yellow' | 'orange' | 'red';

/**
 * @description Discord's message length limit for a user.
 * @param user The signed-in user; a `premiumType` of `2` is Nitro.
 * @returns 4000 for Nitro, otherwise 2000.
 */
export function characterLimit(user: Pick<FluxUser, 'premiumType'> | undefined): number {
	return user?.premiumType === 2 ? 4000 : 2000;
}

/**
 * @description Picks the counter's color as the message approaches the limit.
 * @param length The message length.
 * @param limit The user's message length limit.
 * @param colorEffects Whether the warning colors are turned on.
 * @returns `primary` when warnings are off, otherwise a tone for the share of the limit used.
 */
export function counterTone(length: number, limit: number, colorEffects: boolean): CounterTone {
	if (!colorEffects) return 'primary';

	const used = length / limit;

	if (used < 0.5) return 'muted';
	if (used < 0.75) return 'yellow';
	if (used < 0.9) return 'orange';

	return 'red';
}
```

### components

The pill reads the draft, the Nitro tier and the user's setting:

```tsx src/counter/components/character-counter.tsx excerpt
	const length = useDraftLength(channelId);
	const limit = flux.useStore(UserStore, (store) => characterLimit(store.getCurrentUser()));
	const colorEffects = useSetting('colorEffects');
```

`format('COUNTER_LABEL', { length, limit })` gives its accessibility label. The build redraws it when the language changes.

A constant read by more than one file goes in `src/constants.ts`. A value one file uses stays there. Character Counter's colors try Discord's theme tokens in order, then a fixed fallback:

```ts src/constants.ts quoted
// Each tone tries Discord's theme tokens in order, then a fixed color when the theme has none.
export const TONE_COLORS = {
	primary: { tokens: ['BRAND_330', 'BRAND_500'], fallback: '#5865f2' },
	muted: { tokens: ['TEXT_NORMAL'], fallback: '#f2f3f5' },
	yellow: { tokens: ['YELLOW_330', 'YELLOW_300'], fallback: '#fee75c' },
	orange: { tokens: ['ORANGE_330', 'ORANGE_300'], fallback: '#f0b232' },
	red: { tokens: ['RED_360', 'RED_400'], fallback: '#ed4245' },
};

export const COUNTER_HEIGHT = 20;
```

## Settings

`settings.ts` sits beside `src/` and never ships in the bundle. This one setting becomes a switch with no panel code.

```ts settings.ts quoted
import { defineSettings, setting } from '@unbound-app/settings/schema';

export default defineSettings(
	{
		colorEffects: setting.boolean({
			default: true,
			title: 'COLOR_THRESHOLDS',
			subtitle: 'COLOR_THRESHOLDS_SUBTITLE',
		}),
	},
	{ title: 'APPEARANCE' },
);
```

`title` and `subtitle` are message keys. The generated `src/unbound-settings.d.ts` is why `useSetting('colorEffects')` returns a `boolean`. See [Settings and Storage](/docs/developer/plugins/settings).

## Translations

`i18n/en-US.json` holds every string. Other languages sit beside it and may leave keys out.

```json i18n/en-US.json quoted
{
	"APPEARANCE": "Appearance",
	"COLOR_THRESHOLDS": "Color thresholds",
	"COLOR_THRESHOLDS_SUBTITLE": "Warn as the message approaches Discord’s character limit.",
	"COUNTER_LABEL": "{length} of {limit} characters"
}
```

The generated `src/unbound-i18n.d.ts` makes a missing key a type error in `format`, setting titles and toasts. Commit both generated files so your editor knows the keys before the first build. See [Translations](/docs/developer/plugins/i18n).

## Tests

Tests sit in `tests/`, named after what they cover.

| Kind | How |
| --- | --- |
| Pure logic (`counter/limit.test.ts`, `counter/colors.test.ts`) | Import and call it. The preset is needed only for `~/` |
| Started plugin (`character-counter.test.tsx`) | Register the modules it looks up in `beforeEach`, call `startPlugin()`, render the patched container, read the pill |

```tsx tests/character-counter.test.tsx excerpt
	test('shows the length over the limit while a message is written', () => {
		draft.text = 'hello';

		const counter = renderComposer().find('Text');

		expect(counter.text()).toBe('5/2000');
		expect(counter.props.accessibilityLabel).toBe('5 of 2000 characters');
	});
```

The preset forgets registered modules before each test. See [Writing Tests](/docs/developer/testing/writing-tests).

## Images

Images go in `assets/` beside `src/`. Importing one gives its asset id, and the build copies it into `dist/`. See [Images](/docs/developer/plugins/assets).

## Addon Page

`ADDON.md` has no title; the Marketplace takes the title and summary from the manifest.

```md ADDON.md quoted
---
banner: media/banner.png
---

## :sparkle: What it does

- :text: Shows length over your limit, like `120/2000`, while you type.
- :star: The limit is 4000 characters with Nitro and 2000 without.
- :eye: Hides while the chat input is empty and never changes its layout.
- :arrow-up: Moves up to clear the slowmode notice in channels that have one.

## :gear: Settings

- :color-palette: **Color thresholds** turns the counter yellow at 50% of the limit, orange at 75% and red at 90%. Off, it stays in Discord's brand color. On by default.
```

- The frontmatter names the banner and an optional gallery, both in `media/`.
- No frontmatter builds with a warning, and the Marketplace shows no banner.
- `bun run plugins:banners` draws first-party banners from the manifest and leaves hand-made ones alone.
- `CHANGELOG.md` lists changes newest first. Its version matches `manifest.json`.

See [Addon Page](/docs/developer/publishing/store-page).
