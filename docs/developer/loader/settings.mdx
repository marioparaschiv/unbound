Every key the loader reads or writes in `settings.json`, with its default. The loader keeps all its configuration in this file.

## File Location

| Platform | Path |
| --- | --- |
| iOS | Files app: **On My iPhone → `<App Name>` → Unbound**. See [iOS Loader](/docs/developer/loader/ios). |
| Android | `files/Unbound` in Discord's data directory. See [Android Loader](/docs/developer/loader/android). |

If the file is missing at startup, the loader creates it as `{}`.

Each time `settings.json` loads cleanly, the loader keeps a copy as `settings.json.good`. If the file is ever corrupt, the loader saves it as `settings.json.corrupt-<timestamp>`, keeping the newest three, and restores `settings.json.good`. It resets to `{}` only when there is no good copy.

## Structure

The root is an object of **stores**. The loader reads the `unbound` store, and the applied theme's id from `applied` in the `themes` store. Each addon gets its own store keyed by its id; see [storage](/docs/sdk/latest/storage).

Keys are dot-paths into nested objects. `loader.update.url` is stored as:

```json settings.json
{
	"unbound": {
		"loader": {
			"update": {
				"url": "http://localhost:4040/unbound.bundle"
			}
		}
	}
}
```

<Note>
	The loader shares the `unbound` store with Unbound's JavaScript. Keys it doesn't read, such as `staff-mode` or `toasts.*`, belong to the client and are documented with their features.
</Note>

## Keys

All keys are in the `unbound` store.

<ParamField path="loader.enabled" type="boolean" default="true">
	Turns the loader on or off. When `false`, it logs `Loader is disabled. Aborting.` and hands the bundle load back to Discord: no plugins, themes, fonts, updater or hot reload. See [Disabling the Loader](#disabling-the-loader).
</ParamField>

<ParamField path="loader.devtools" type="boolean" default="false">
	Runs the bundled React DevTools backend before the main bundle. The DevTools app reaches it over the debugger. See [React DevTools](/docs/developer/tools/debugger#react-devtools-and-the-view-tree).
</ParamField>

<ParamField path="loader.telemetry.block" type="boolean" default="true">
	Answers Discord's own analytics requests (`/api/v*/science` and `/api/v*/metrics` on `discord.com`) locally with `204 No Content`, so they never leave the device. This backs up the client's tracking builtin for requests that run before it or around it.
</ParamField>

<ParamField path="loader.update" type="object">
	Where the bundle downloads from and when it is refetched.

	<Expandable title="properties">
		<ParamField path="loader.update.url" type="string" default="'https://builds.unbound.rip/'">
			The bundle source. Empty uses the build's default (`https://builds.unbound.rip/` for releases); on a simulator or emulator, a dev server on the host's port 3000 wins.

			- Ending in `.bundle` or `.js`: names the file; its folder is the source.
			- Otherwise: the source folder.

			Fetches `manifest.json` and `manifest.json.sig`, then `unbound.<bytecode version>.bundle` if the manifest lists the app's Hermes bytecode version, or `unbound.js` otherwise; the download must match the signed SHA-512. A new bundle stays a candidate until Discord has run with it for 15 seconds, gone to the background, or reloaded. A manifest byte-for-byte equal to the active bundle's skips the signature and bundle requests.

			Also sets the hot reload origin (scheme and host). See [Bundle Updates](/docs/developer/loader/android#bundle-updates) for every check.
		</ParamField>

		<ParamField path="loader.update.force" type="boolean" default="false">
			Redownloads every launch instead of sending the stored ETag as `If-None-Match` and keeping the file on `304`.
		</ParamField>

		<ParamField path="loader.update.hmr" type="boolean" default="false">
			Opens a hot reload connection to the origin of `loader.update.url`, and reloads Discord once a newer bundle downloads. No connection if the URL is empty or lacks a scheme and host.
		</ParamField>

		<ParamField path="loader.update.unsigned" type="boolean" default="false">
			Skips the bundle signature check. Only needed for your own build on a non-local server: `localhost`, `*.localhost`, `*.local`, `::1` and private IPv4 hosts skip it already.
		</ParamField>

		<ParamField path="loader.update.baseline" type="string" default="''">
			Set by the loader. Records the source, channel and build time of the active signed bundle, to refuse updates from another channel or older builds.
		</ParamField>

		<ParamField path="loader.update.etag" type="string" default="''">
			Set by the loader. The `etag` of the last successful download. Delete it to force one full download.
		</ParamField>
	</Expandable>
</ParamField>

<ParamField path="recovery" type="boolean" default="false">
	Recovery Mode. When on, the loader skips the native theme, and the client starts addons as empty no-ops; addon cards show but can't be used. The toolbox toggles it and reloads. See [Troubleshooting](/docs/user/troubleshooting).

	The loader turns it on by itself after Discord closes during startup three launches in a row; a launch counts once Discord has run for 15 seconds or gone to the background. After two such launches, it first goes back to the bundle its last update replaced.
</ParamField>

<ParamField path="font-states" type="object" default="{}">
	Legacy font overrides. On first launch the loader moves overrides naming an installed font file into `Fonts/state.json`, drops ones naming a system font, and Unbound removes this key.
</ParamField>

<ParamField path="toolbox.shake" type="boolean" default="true">
	Opens the toolbox when you shake the device.
</ParamField>

<ParamField path="toolbox.three-finger" type="boolean" default="true">
	Opens the toolbox when you hold three fingers on the screen. Turning one gesture off turns the other on, so you can't lock yourself out.
</ParamField>

<ParamField path="dev-overlay.position" type="object">
	Set by the loader. Where you dragged the dev overlay button, as `x` and `y` fractions of the screen.
</ParamField>

<Note>
	The iOS toolbox's **Use Unbound Icon** switch isn't stored here. It sets the app's alternate icon directly.
</Note>

## Live Edits

Edits from the Files app, SSH or any tool apply without a restart: the loader watches and reparses the file.

- Keys read once at launch, such as `loader.enabled` and `loader.devtools`, still need a restart.
- In-app writes are debounced by 300ms, so a burst of changes is one write.

## Corrupt Files

If the file fails to parse, or isn't a JSON object, the loader:

1. Copies it to `settings.json.corrupt-<timestamp>` (Unix seconds), for example `settings.json.corrupt-1753488000`.
2. Resets `settings.json` to `{}`.
3. Keeps starting up.

## Disabling the Loader

Set `loader.enabled` to `false` to get a stock app without uninstalling. The check runs before any plugin, theme or bundle work.

```json settings.json
{
	"unbound": {
		"loader": {
			"enabled": false
		}
	}
}
```

Use it when a bad bundle or addon blocks the UI. To only sideline addons, use `recovery` instead; it changes less.
