The **loader** is the native part of Unbound. It's a tweak on iOS and an Xposed module on Android. Its job is to get Unbound's JavaScript bundle running inside Discord, before Discord's own. Addon developers don't need it. Read on if you work on Unbound itself, or want to know what happens at launch.

## What happens at launch

Each time Discord loads its JavaScript, the loader runs these steps first.

<Flow>
	<FlowStep title='Read settings.json' detail='Stop here if loader.enabled is false' />
	<FlowStep title='Scan addon folders' detail='Plugins, Themes, Fonts' />
	<FlowStep title="Run Unbound's bundle" detail='The cached copy' />
	<FlowStep title="Run Discord's bundle" />
</Flow>

The loader never runs plugins itself. It reads them from disk, and hands them to Unbound's JavaScript in globals such as `UNBOUND_PLUGINS` and `UNBOUND_THEMES`. Unbound's bundle starts and stops them.

Running first is what lets Unbound hook Metro before Discord defines its modules. See [Concepts](/docs/developer/concepts).

## What else it does in native code

- **Updates the bundle.** It downloads a newer bundle in the background, checks its signature and hash, and uses it from the next launch.
- **Applies the theme and fonts.** Colors and fonts are swapped below JavaScript, so they cover native views too.
- **Guards against crashes.** When two launches in a row end inside the same addon, Unbound turns that addon off.
- **Opens the toolbox.** The recovery menu works even when Unbound's JavaScript fails to load.
