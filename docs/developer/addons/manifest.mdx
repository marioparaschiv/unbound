`manifest.json` tells Unbound who an addon is: its id, name, authors and version. Every [plugin](/docs/developer/plugins/introduction), [theme](/docs/developer/themes/introduction) and [icon pack](/docs/developer/icon-packs/introduction) ships one, in the same shape.

```json manifest.json
{
	"id": "my-plugin",
	"name": "My Plugin",
	"description": "Adds something useful to Discord.",
	"authors": [{ "name": "you", "id": "1234567890" }],
	"version": "1.0.0",
	"main": "index.tsx"
}
```

## Required fields

Unbound rejects an addon that leaves any of these out, or has an empty `authors`.

<ParamField path='id' type='string' required>
	A unique identifier for the addon. It names your [settings](/docs/developer/plugins/settings) Bucket and identifies the addon to Unbound, so choose it once and never change it.
</ParamField>
<ParamField path='name' type='string' required>
	The human-readable name shown in settings.
</ParamField>
<ParamField path='description' type='string' required>
	A short summary of what the addon does.
</ParamField>
<ParamField path='authors' type='AddonAuthor[]' required>
	A non-empty array of authors. An empty array fails validation, the same as a missing field.

	<Expandable title='AddonAuthor'>
		<ParamField path='name' type='string' required>
			The author's display name.
		</ParamField>
		<ParamField path='id' type='string' required>
			The author's Discord user id.
		</ParamField>
	</Expandable>
</ParamField>
<ParamField path='version' type='string' required>
	The addon's version. Increase it on every release so clients can detect updates.
</ParamField>
<ParamField path='main' type='string' required>
	The entry file the bundle is built from, relative to `src/`, such as `index.tsx`. The build writes the bundle's name, `index.js`, into the manifest it ships. Themes ignore this field. See [Themes](#themes) below.
</ParamField>

## Optional fields

Used for display and updates. You can leave them out.

<ParamField path='icon' type='string | { uri: string }'>
	The addon's icon: an [asset](/docs/api/latest/assets) name, or an object with a `uri` for a remote image.
</ParamField>
<ParamField path='updates' type='string'>
	A URL Unbound checks to discover newer versions.
</ParamField>
<ParamField path='url' type='string'>
	Where the addon's bundle is hosted.
</ParamField>

## What each kind adds

Every kind uses the same manifest. A few kinds need an extra file or field.

<AccordionGroup>
	<Accordion title='Plugins' icon='plug'>
		Nothing extra. `main` names your entry file in `src/`, and `ubd build` turns it into the bundle. See [Your First Plugin](/docs/developer/addons/creating).
	</Accordion>
	<Accordion title='Themes' icon='paintbrush'>
		A theme ships a **`bundle.json`** next to its manifest, holding the palette and background. See [Theme Colors](/docs/developer/themes/types).

		<Warning>
			Themes ignore `main`. The field is still required, but Unbound always reads `bundle.json`. If your colors don't apply, check the file's name.
		</Warning>
	</Accordion>
	<Accordion title='Icon Packs' icon='shapes'>
		An icon pack is a **folder of image files** laid out like Discord's assets. Its manifest adds two fields:

		<ParamField path='type' type="'icon-pack'">
			Marks the manifest as an icon pack. If the field is present at install time, it must be `'icon-pack'`, or the install is rejected.
		</ParamField>
		<ParamField path='source' type="'github' | 'other'">
			How the pack's files are fetched. If omitted, it is inferred from `main`: a `github.com` URL means `github`, and anything else means `other`.
		</ParamField>

		How `main` is used depends on `source`:

		- `github`: `main` is the repo URL, optionally with a `/tree/<branch>/<path>` suffix. Unbound downloads the images in that tree into the pack folder.
		- `other`: the pack installs from `main` like any other addon.

		See [Icon Packs](/docs/developer/icon-packs/introduction).
	</Accordion>
	<Accordion title='Fonts' icon='text-a'>
		A font has no manifest. It's a single font file, and Unbound names it after the full name stored inside the file. See [Fonts](/docs/user/fonts) for how users apply one.
	</Accordion>
</AccordionGroup>
