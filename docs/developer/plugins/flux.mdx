### What is Flux?

Flux is how Discord manages its state. A central dispatcher broadcasts actions, such as a message arriving, a channel being selected, or the user's settings changing. Stores listen for those actions and hold the resulting state.

- To get *what* Discord currently knows (the current user, a guild, the selected channel), read a store.
- To run code *when* something happens, listen for an action.

Both go through the [flux](/docs/api/latest/flux) namespace.

### Reading stores

A store is a singleton with getters for Discord's state. `flux.getStore` is lazy, so you can declare the store at the top of a file. The search runs the first time you read from it.

```ts
import { flux } from '@unbound-app/api';

const UserStore = flux.getStore('User');

// later, inside start() or a handler:
const me = UserStore.getCurrentUser();
```

In a component, read the store with `flux.useStore` so the component re-renders when the store changes. See [Reading a store in a component](/docs/api/latest/flux).

### Listening for actions

Listen for an action type to run code each time Discord dispatches it.

```ts
import { flux } from '@unbound-app/api';

export default {
	start() {
		flux.onAction('CHANNEL_SELECT', ({ channelId }) => {
			logger.log('Channel selected:', channelId);
		});
	},
};
```

You don't need a `stop` for this. Unbound removes the plugin's Flux listeners and interceptors when the plugin stops. To remove a listener earlier, call the function `onAction` returns.

### Common action types

Discord dispatches hundreds of action types. These are some you'll see often:

<AccordionGroup>
	<Accordion title='Messages' icon='message'>
		`MESSAGE_CREATE`, `MESSAGE_UPDATE`, `MESSAGE_DELETE`, fired when messages are sent, edited, or deleted.
	</Accordion>
	<Accordion title='Navigation' icon='compass'>
		`CHANNEL_SELECT`, `GUILD_SELECT`, fired when the user switches channels or servers.
	</Accordion>
	<Accordion title='Connection' icon='wifi'>
		`CONNECTION_OPEN`, fired once the client is connected and stores are populated. Use it for setup that needs live state.
	</Accordion>
</AccordionGroup>

`MESSAGE_CREATE`, `MESSAGE_UPDATE`, `MESSAGE_DELETE`, `CHANNEL_SELECT`, `TYPING_START`, `TYPING_STOP` and `CONNECTION_OPEN` have typed payloads. To type another action, see [Typing your own stores and actions](/docs/api/latest/flux).
