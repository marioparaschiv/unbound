A plugin has two ways into Discord's state. It reads a **Flux store** to get what Discord knows right now, and it listens for a **Flux action** to run code when something happens.

## Reference

Every function is on `flux`, from `@unbound-app/api`.

| Function | Does |
| --- | --- |
| `flux.getStore(name, options?)` | Returns the typed store named `name`, such as `'User'` for `UserStore`. Lazy by default. `options`: `lazy`, and `short: false` to match the full name |
| `flux.useStore(stores, selector, options?)` | In a component, returns `selector(stores)`. Re-renders only when the result changes. `options`: `deps`, `isEqual` |
| `flux.onAction(type, listener)` | Calls `listener` with each action of `type`, after Discord's stores handle it. Returns a function that removes it |
| `flux.interceptAction(type, interceptor)` | Calls `interceptor` before Discord handles each action of `type`. It may change the action, or return `true` to drop it. Returns a function that removes it |
| `flux.onStoreChange(store, listener)` | Calls `listener` after each change to `store`. Returns a function that removes it |
| `flux.dispatch(action)` | Sends an action through Discord's dispatcher. Resolves once the stores handled it |

The typed stores are `User`, `Guild`, `GuildMember`, `Channel`, `SelectedChannel`, `Typing`, `Relationship`, `UserProfile` and `GuildSettings`. Any other name returns a base store with `getName`, `addChangeListener`, `removeChangeListener` and `emitChange`. The scope removes every listener and interceptor when the plugin stops.

## How Flux works

When something happens, such as a message arriving or the user switching channel, Discord **dispatches an action**. **Stores** listen for actions and update the state they hold.

## Reading a store

A store is a single object with getters for its state. `flux.getStore` is lazy, so you can declare the store at the top of a file. It is also typed. Prefer it to `metro.stores`, which holds the same stores without their types. See [Pick the lookup that costs least](/docs/developer/plugins/metro#pick-the-lookup-that-costs-least).

```ts
import { flux } from '@unbound-app/api';

const UserStore = flux.getStore('User');

export function currentUsername() {
	return UserStore.getCurrentUser()?.username;
}
```

In a component, read the store with `flux.useStore` instead. Pass the store and a selector. The selector gets the store, and the component re-renders only when the value it returns changes.

```tsx
import { Discord } from '@unbound-app/api/metro/components';
import { flux } from '@unbound-app/api';

const UserStore = flux.getStore('User');

function Username() {
	const username = flux.useStore(UserStore, (store) => store.getCurrentUser()?.username);

	return <Discord.Text variant='text-md/medium'>{username}</Discord.Text>;
}
```

To read several stores, pass them as an array. The selector gets the same array. If the selector uses a prop, pass it in `deps`, so the value is read again when it changes.

```ts
import { flux } from '@unbound-app/api';

const ChannelStore = flux.getStore('Channel');
const UserStore = flux.getStore('User');

export function useChannelLabel(channelId: string) {
	return flux.useStore(
		[ChannelStore, UserStore],
		([channels, users]) =>
			`${channels.getChannel(channelId)?.name} as ${users.getCurrentUser()?.username}`,
		{ deps: [channelId] },
	);
}
```

A selector that returns a new object or array re-renders the component on every store change, because the new value is never `===` the old one. Wrap it in `utils.react.useShallow`. The component then re-renders only when a top-level field changes.

```ts
import { flux, utils } from '@unbound-app/api';

const UserStore = flux.getStore('User');

export function useIdentity() {
	return flux.useStore(
		UserStore,
		utils.react.useShallow((store) => ({
			username: store.getCurrentUser()?.username,
			avatar: store.getCurrentUser()?.avatar,
		})),
	);
}
```

For any other comparison, pass `isEqual`. It gets the old and new values, and returns `true` to skip the re-render. `utils.react.shallow` is the comparison `useShallow` uses. See [flux](/docs/sdk/latest/flux) in the SDK reference.

## Listening for an action

Pass the action's type and a callback. The callback gets the action's payload each time Discord dispatches it.

```ts src/channel-log/index.ts
import { flux } from '@unbound-app/api';

export function startChannelLog() {
	flux.onAction('CHANNEL_SELECT', ({ channelId }) => {
		logger.log('Channel selected:', channelId);
	});
}
```

Unbound removes the listener when your plugin stops. To remove it sooner, call the function `onAction` returns.

## Common actions

Discord dispatches hundreds of action types. These are the ones you'll use most:

| Action | Dispatched when |
| --- | --- |
| `MESSAGE_CREATE`, `MESSAGE_UPDATE`, `MESSAGE_DELETE` | A message is sent, edited or deleted |
| `CHANNEL_SELECT`, `GUILD_SELECT` | The user switches channel or server |
| `TYPING_START`, `TYPING_STOP` | Someone starts or stops typing |
| `CONNECTION_OPEN` | The client connects and the stores fill. Use it for setup that needs live state |

All of these except `GUILD_SELECT` have typed payloads. To type another action, see [Typing your own stores and actions](/docs/sdk/latest/flux).
