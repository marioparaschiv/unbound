Import an image like a module. A PNG, JPEG, WebP or GIF import is the image's asset id, for `source` props. An SVG import is an icon component, for `IconComponent` and `icon` props; see [SVGs](#svgs).

```tsx
import { Image } from 'react-native';
import star from '../assets/icons/star.png';

export function Rating() {
	return <Image source={star} style={{ width: 24, height: 24 }} />;
}
```

That's all the setup there is. `ubd build` copies the file into `dist/`, lists it in the built manifest, and Unbound registers it with Discord's asset registry when your plugin starts. The id works anywhere Discord takes an image `source`:

```tsx
import { Discord } from '@unbound-app/api/metro/components';
import star from '~/images/star.png';

<Discord.TableRow label='Favourites' icon={<Discord.TableRowIcon source={star} />} />;
```

An image can live anywhere in your plugin. Import it with a relative path or `~/`, which points at `src/`.

## Formats and sizes

| Format | Extensions |
| --- | --- |
| PNG | `.png` |
| JPEG | `.jpg`, `.jpeg` |
| WebP | `.webp` |
| GIF | `.gif` |
| SVG | `.svg` |

An SVG works differently; see [SVGs](#svgs). Anything else fails the build with the file's name.

For sharp images on every screen, put the larger versions beside the file with an `@2x` or `@3x` suffix. You import only the plain name, and Unbound picks the right file for the device:

```
assets/icons/star.png      24 × 24
assets/icons/star@2x.png   48 × 48
assets/icons/star@3x.png   72 × 72
```

The build reads each image's width and height, so `<Image source={star} />` has its size in points without a `style`. You can ship only `@3x`; the size is still in points.

## SVGs

Importing an SVG gives you an icon component that behaves like Discord's own, such as `WrenchIcon`. Pass the component where a prop takes one, and an element where a prop takes a node:

```tsx
import { Discord } from '@unbound-app/api/metro/components';
import Star from '../assets/star.svg';

<Discord.TableRow label='Favourites' icon={<Discord.TableRowIcon IconComponent={Star} />} />;
<Discord.ActionSheetRow label='Favourite' icon={<Discord.ActionSheetRow.Icon IconComponent={Star} />} />;
<Discord.IconButton icon={<Star />} />;
```

Unbound's own APIs take any icon: an asset id, an element or a component.

```tsx
import { toasts, ui } from '@unbound-app/api';

toasts.show({ title: 'Starred', icon: Star });
<ui.Row label='Favourites' icon={Star} />;
```

| Prop | Takes | The icon gets |
| --- | --- | --- |
| `TableRowIcon` and `ActionSheetRow.Icon` `IconComponent` | A component | `size` and `color` for the row's variant |
| A settings entry's `IconComponent` | A component | The same, through `TableRowIcon` |
| `MenuItem` and `ContextMenuItem` `IconComponent` | A component | `size: 'sm'`, and `color` in a context menu |
| `TableRow`, `ActionSheetRow`, `Button` and `IconButton` `icon` | An element | Nothing: it draws at its own size and colour |
| `ui.Row`, `ui.SwitchRow`, `toasts.show` `icon`, a toast button's `icon` | An asset id, element or component | A component draws through `TableRowIcon`, or at `md` in a toast |

**Size and colour.** The component takes Discord's icon props. `size` is `'xxs'` (12), `'xs'` (16), `'sm'` (18), `'md'` (24, the default), `'lg'` (32), a number of points, or `'custom'` to size it with `style`. `width` and `height` still win when you pass them. `color` is a theme token, such as `Theme.colors.TEXT_LINK`, or a colour. Without one, the icon takes the theme's icon colour, so it matches Discord's icons in every theme.

**Tinting.** If the SVG draws in one solid colour, counting the default black fill, the build swaps that colour for `currentColor`, which `color` sets. An SVG that uses two or more colours, gradients, masks, `<style>` or `class` is left as drawn, and `color` doesn't change it. To show a one-colour SVG in its own colour, pass that colour as `color`.

**Cleaning.** The build drops comments, the doctype, editor metadata (`<metadata>`, `sodipodi:*`, `inkscape:*`) and the whitespace between tags. A file that isn't well-formed XML, or whose root isn't `<svg>`, fails the build with the reason.

**Loading.** Nothing loads when your plugin starts. `react-native-svg` and the theme are read the first time a component renders. The cleaned markup is inlined in your bundle once per file, however many times you import it. The build warns about an SVG over 32 KB: simplify it, or export it as a PNG.

An SVG is never registered as an asset, so it has no asset id. For a `source` prop, export a PNG.

## Looking images up by name

Each image also has a name: its path without the extension or scale suffix. Under the plugin's `assets/` folder the name starts inside that folder, so `assets/icons/star.png` is `icons/star`. Anywhere else it starts at the plugin root, so `src/images/star.png` is `src/images/star`.

```ts
import { assets } from '@unbound-app/api';

const star = assets.getIdByName('icons/star');
```

Inside your plugin, `getIdByName` and `getByName` find your own names first, then Discord's. Two plugins can both have an `icons/star` without either seeing the other's.

<Note>
	An imported image always ships. An image in `assets/` that nothing imports ships only when your code spells out its name, as in `getIdByName('icons/star')`. The build warns about every image it leaves out. A name you build at runtime, such as `` `icons/${kind}` ``, isn't spelled out, so import those images instead.
</Note>

## Images you make at runtime

`assets.register` registers an image your plugin creates while it runs, such as a `data:` URI or a file you wrote with `fs`. It returns the id and a function that unregisters it.

```ts
import { assets, fs } from '@unbound-app/api';

const avatar = assets.register({
	name: 'avatar',
	path: `${fs.documentsPath}/MyPlugin/avatar.png`,
	width: 32,
	height: 32,
	type: 'png',
});

<Image source={avatar.id} />;
```

| Option | What it does |
| --- | --- |
| `name` | The name `getIdByName` finds it by. Registering a name again reuses its id |
| `uri` or `path` | The image at scale 1: a URI such as `data:` or `https:`, or an absolute file path |
| `width`, `height` | Its size in points |
| `type` | Its file type, such as `png` |
| `scales` | The image at other densities, by scale: `{ 2: uri, 3: uri }` |

Everything your plugin registers, imported images included, is unregistered when it stops. An unregistered id draws nothing.

## While you develop

`ubd dev` rebuilds your plugin when you add, edit or replace an image, and the next push carries the new file to the device. Files are named by their content, so a replaced image never shows the old one from a cache.
