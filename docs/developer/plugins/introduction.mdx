A plugin is a bundle of JavaScript that Unbound loads and runs inside Discord. It finds Discord's code with Metro, changes it with the patcher, and saves options with storage. This page covers what happens to that bundle from the moment the user turns it on.

## The shape of a plugin

A plugin's entry file default-exports an object. Every member is optional.

```tsx src/index.tsx
export default {
	start() {
		// set up patches, listeners and commands
	},
	stop() {
		// undo what the Addon scope can't see
	},
	getSettingsPanel: () => <Settings />,
};
```

| Member | When Unbound calls it |
| --- | --- |
| `start` | When the plugin is turned on, and at launch if it was on |
| `stop` | When the plugin is turned off. A returned promise is awaited |
| `getSettingsPanel` | When the user opens the plugin's settings. See [Settings and Storage](/docs/developer/plugins/settings) |

## The lifecycle

Each time the plugin starts, Unbound evaluates its bundle again with a fresh Addon scope, then calls `start`. When the user turns it off, Unbound calls `stop`, then disposes the scope.

<Flow>
	<FlowStep title='Evaluate' detail='Top-level code runs' />
	<FlowStep title='start()' detail='Set everything up' />
	<FlowStep title='Running' />
	<FlowStep title='stop()' detail='Undo the rest' />
	<FlowStep title='Scope disposed' detail='Removes what it recorded' added />
</Flow>

The top level of your files runs during evaluation, before `start`. At launch, that delays Discord itself, so keep it cheap.

<Warning>
	Make no eager [Metro](/docs/developer/plugins/metro) search at the top level. `metro.find` and any search with `{ lazy: false }` walk every module right away. The `findBy*` helpers and `flux.getStore` are lazy by default, so they're safe there.
</Warning>

## The Addon scope

Each plugin runs with its own **Addon scope**: a set of globals that belong to it. Everything the plugin registers through them is recorded. After `stop` returns, the scope removes it all, newest first. So `stop` only has to undo what the scope can't see.

| Global | What it is |
| --- | --- |
| `unbound` | The API. Its `patcher`, `commands`, `metro`, `storage` and `flux` are the plugin's own versions |
| `addon` | The plugin's handle: `id`, `name`, `version`, `manifest` and its state |
| `logger` | A logger that prefixes every line with the plugin's name |
| `setTimeout`, `setInterval` | Timers that are cleared when the plugin stops |
| `React` | React |

Imports from `@unbound-app/api` read from the scoped `unbound`. So `import { patcher } from '@unbound-app/api'` gives the plugin its own patcher. The scope removes:

- Patches and slash commands.
- Timers from `setTimeout` and `setInterval`.
- Listeners from `metro.onModuleLoad`, and `metro.findLazy` waits that haven't resolved.
- Listeners from `storage.onChange`.
- Listeners and interceptors from `flux.onStoreChange`, `flux.onAction` and `flux.interceptAction`.

```ts src/channel-log/index.ts
import { flux, storage } from '@unbound-app/api';

const settings = storage.getBucket();

export function startChannelLog() {
	flux.onAction('CHANNEL_SELECT', ({ channelId }) => {
		settings.set('lastChannel', channelId);
		logger.log('Selected', channelId);
	});
}
```

This feature needs no `stop`. The scope removes the Flux listener when the plugin stops.

### What `stop` still has to undo

The scope only sees what went through it. Undo these yourself:

- A listener you added straight to a Discord module.
- A settings section you registered.
- Anything a patched component already rendered. [Cleaning up](/docs/developer/plugins/react-patching#cleaning-up) shows how to re-render it.

Themes, icon packs and fonts ship no code, so they have no scope.

## Keeping a plugin fast

A plugin should cost almost nothing until it's used. Two habits get you there.

<Steps>
	<Step title='Keep lookups lazy' icon='clock'>
		Declare Metro lookups with the lazy `findBy*` helpers. The search runs the first time you read from the result, inside `start` or later in a handler.

		```ts
		const Messages = metro.findByProps('sendMessage', 'receiveMessage');
		```
	</Step>
	<Step title='Load heavy code on demand' icon='code-branch'>
		Move code that pulls in many modules into its own file, and `import()` it inside `start`. That code then loads only when the plugin runs.

		```ts src/index.tsx
		export default {
			async start() {
				const { startEditor } = await import('~/editor');

				startEditor();
			},
		};
		```
	</Step>
</Steps>
