Discord's screens are React components your plugin doesn't own. To change one, you patch its render, usually with an `after` patch, and edit the elements it returns. Your changes become part of Discord's real tree, so they can use its context and survive its re-renders.

Read [Patching Functions](/docs/developer/plugins/patching) first. This page applies the same patcher to components.

## Reference

`patcher.react` has `before`, `after` and `instead`. Each takes a component or the object and key that hold it, and returns a function that removes the patch.

| Call | Runs | Callback returns |
| --- | --- | --- |
| `patcher.react.before(target, callback, options?)`<br />`patcher.react.before(parent, key, callback, options?)` | Before the component renders | New props, or nothing |
| `patcher.react.after(target, callback, options?)`<br />`patcher.react.after(parent, key, callback, options?)` | After it renders | A tree to replace `result`, or nothing |
| `patcher.react.instead(target, callback, options?)`<br />`patcher.react.instead(parent, key, callback, options?)` | In place of it | The tree to render |

`target` is a `memo`, `forwardRef` or class component. A plain function has no wrapper to patch, so it needs `parent` and `key`. Each callback gets:

| Field | Holds |
| --- | --- |
| `props` | The props of this render. For a class component, `this.props` |
| `result` | What the component rendered, after earlier patches. `after` only |
| `original` | Renders the unpatched component. Pass new props to render a function component with those. A class component ignores them |
| `this` | The class instance rendering, or `undefined` for a function component |

Helpers for the tree a render returns, from `utils`:

| Function | Returns |
| --- | --- |
| `utils.react.findComponent(tree, match)` | The first element that `match` picks, or `undefined` |
| `utils.react.filterComponents(tree, match)` | Every element that `match` picks |
| `utils.findInTree(root, predicate, options?)`<br />`utils.filterInTree(root, predicate, options?)` | The first match, or every match, in any object |
| `utils.react.findInTree(root, predicate, options?)`<br />`utils.react.filterInTree(root, predicate, options?)` | The same, through the keys React's elements and fibers use |
| `utils.react.useShallow(selector)`, `utils.react.shallow(a, b)` | A selector that skips a re-render when its result is shallow-equal, and the comparison it uses |

`match` is a component name, a host type such as `'RCTView'`, or a function that gets each element and returns `true`.

## Patching a render

Pass the module that holds the component and its key, and return the tree you want.

```tsx src/toasts/index.tsx
import { metro, patcher } from '@unbound-app/api';

const Toasts = metro.findByProps('ToastContainer');

export function startToastPatch() {
	patcher.react.after(Toasts, 'ToastContainer', ({ props, result }) => {
		// wrap, replace, or return the original tree
		return result;
	});
}
```

Like every patch, this waits for a [lazy lookup](/docs/developer/plugins/metro#searches-are-lazy) to load, so it never makes Discord load the module early.

<Tabs>
	<Tab title='after'>
		Runs after the component renders. Return a tree to replace `result`, or nothing to keep it.

		```tsx
		import { metro, patcher } from '@unbound-app/api';

		const Profile = metro.findByProps('UserProfile');

		patcher.react.after(Profile, 'UserProfile', ({ props, result }) => {
			logger.log('Rendering profile of', props.userId);

			return result;
		});
		```
	</Tab>
	<Tab title='before'>
		Runs before the component renders. Return new props to render with those instead.

		```tsx
		import { metro, patcher } from '@unbound-app/api';

		const Profile = metro.findByProps('UserProfile');

		patcher.react.before(Profile, 'UserProfile', ({ props }) => {
			return { ...props, compact: true };
		});
		```

		A class component renders from `this.props`, so a `before` patch cannot replace them. [Patching class components](#patching-class-components) shows what to do instead.
	</Tab>
	<Tab title='instead'>
		Renders your return value in place of the component. Call `original` when you still want Discord's tree.

		```tsx
		import { metro, patcher } from '@unbound-app/api';

		const Profile = metro.findByProps('UserProfile');

		patcher.react.instead(Profile, 'UserProfile', ({ props, original }) => {
			if (props.isBot) return null;

			return original();
		});
		```
	</Tab>
</Tabs>

Every patch returns a function that removes it, and takes `{ once: true }` as its last argument, as in [Undoing a patch](/docs/developer/plugins/patching#undoing-a-patch).

## Where the render function lives

Each kind of component keeps its render in a different place. `patcher.react` looks the kind up and patches the right one:

| Component | `patcher.react` patches |
| --- | --- |
| `React.memo` | The wrapped component on `.type`, unwrapping a `forwardRef` or class inside |
| `React.forwardRef` | `.render` |
| Class | `prototype.render` |
| Plain function | The key that holds it |

You can also pass a `memo`, `forwardRef` or class component by itself, such as `patcher.react.after(SomeMemo, callback)`. A plain function has no wrapper to patch, so it needs the object holding it and its key. Passed alone, it throws.

<Note>
	Passing the component itself reads it, so a lazy lookup loads its module right away. Pass the module and key to keep the patch waiting.
</Note>

## Reaching into a render

A render result is a tree of React elements. On each element, `type` is the component, `props` its props, and `props.children` what it renders inside. `utils.react.findComponent` walks that tree and returns the first element that matches. `utils.react.filterComponents` returns every match instead.

```tsx
import { metro, patcher, utils } from '@unbound-app/api';

const Profile = metro.findByProps('UserProfile');

patcher.react.after(Profile, 'UserProfile', ({ result }) => {
	const row = utils.react.findComponent(result, 'Row');

	if (row) {
		row.props.style = [row.props.style, { opacity: 0.5 }];
	}

	return result;
});
```

Other plugins may patch the same component, so:

- Guard every lookup. `findComponent` returns `undefined` when Discord changes its tree, or another plugin already has.
- Add to `children` instead of replacing it. Replacing it removes what earlier plugins added.

## Patching a child for one render

Some children are created fresh on every parent render. A patch left on one targets a component that no longer exists on the next render. Patch it from inside the parent's patch instead, with `{ once: true }`, so the child's patch lasts for exactly one render.

```tsx
import { metro, patcher, utils } from '@unbound-app/api';

const Profile = metro.findByProps('UserProfile');

patcher.react.after(Profile, 'UserProfile', ({ result }) => {
	const child = utils.react.findComponent(result, 'ProfileBadges');

	if (child && typeof child.type !== 'string') {
		patcher.react.after(child.type, ({ result: badges }) => badges, { once: true });
	}

	return result;
});
```

This works when `child.type` is a `memo`, `forwardRef` or class. For a plain function, patch it where its module exports it.

## Patching class components

`patcher.react` patches a class's `render`. Its other members live in three places, and each is patched differently. Check where a member lives before you patch it:

```ts
import { metro } from '@unbound-app/api';

const SomeClass = metro.findByName('SomeClass', { lazy: false });

Object.hasOwn(SomeClass.prototype, 'componentDidMount'); // true: a prototype method
Object.hasOwn(SomeClass, 'getDerivedStateFromProps'); // true: a static method
Object.hasOwn(SomeClass.prototype, 'onPress'); // false: a class field, on each instance
```

<Tabs>
	<Tab title='Prototype method'>
		Lifecycle methods and methods declared as `name() {}` live on the prototype. Patch them there with the regular patcher. Mounted instances call the patched method from their next call on, because they read it from the prototype.

		```tsx
		import { metro, patcher } from '@unbound-app/api';

		const SomeClass = metro.findByName('SomeClass');

		patcher.after(SomeClass.prototype, 'componentDidUpdate', ({ this: instance }) => {
			logger.log('Updated with', instance.props);
		});
		```

		A mounted instance has already run `componentDidMount`, so a patch on it only runs for instances mounted afterwards.
	</Tab>
	<Tab title='Class field'>
		A field written as `onPress = () => {}` is created on each instance in the constructor, so the prototype doesn't have it. Patch `render` to reach each instance as `this`, then patch the instance itself, once. Use `before`, so the render that reached the instance already passes the patched field down.

		```tsx
		import { metro, patcher } from '@unbound-app/api';

		const SomeClass = metro.findByName('SomeClass');
		const patched = new WeakSet<object>();

		patcher.react.before(SomeClass, ({ this: instance }) => {
			if (patched.has(instance)) return;

			patched.add(instance);
			patcher.before(instance, 'onPress', () => {
				logger.log('Pressed');
			});
		});
		```

		The instance patches are yours too, so the scope removes them when the plugin stops.
	</Tab>
	<Tab title='Static method'>
		A `static` method lives on the class itself. Patch it there.

		```tsx
		import { metro, patcher } from '@unbound-app/api';

		type SomeClassStatics = {
			getDerivedStateFromProps(props: { compact?: boolean }, state: object): object;
		};

		// `metro.find` returns `any`, so the lookup takes the type you give it.
		const SomeClass: SomeClassStatics = metro.find(metro.filters.byName('SomeClass'));

		patcher.after(SomeClass, 'getDerivedStateFromProps', ({ args: [props], result }) => {
			return { ...result, compact: props.compact ?? false };
		});
		```
	</Tab>
	<Tab title='Constructor'>
		To run code when an instance is created, patch the class where its module exports it. The patcher calls the original with `new`, and `result` is the new instance.

		```tsx
		import { metro, patcher } from '@unbound-app/api';

		const SomeClassModule = metro.findByProps('SomeClass');

		patcher.after(SomeClassModule, 'SomeClass', ({ result: instance }) => {
			logger.log('Created', instance);
		});
		```

		The patch only sees instances created after it, through that export. Instances already mounted have run their constructor.
	</Tab>
</Tabs>

### Change a class component's props with a component swap

A patch on a class component cannot change its props. `before` patches cannot replace `this.props`, and `original` ignores the props you pass it. To render a class with other props, patch the component that renders it, and swap the element's `type` for a function component that renders the class with the props you want.

```tsx
import { metro, patcher, utils } from '@unbound-app/api';

const Profile = metro.findByProps('UserProfile');
const ProfileRow = metro.findByName('ProfileRow');

// Declared once at the top level: a new function on each render would remount the row every time.
function CompactProfileRow(props: Record<string, unknown>) {
	return <ProfileRow {...props} compact />;
}

patcher.react.after(Profile, 'UserProfile', ({ result }) => {
	const row = utils.react.findComponent(result, 'ProfileRow');

	if (row) row.type = CompactProfileRow;

	return result;
});
```

React compares the element's `type` between renders. A swap to the same function every time keeps the row's state. The swap goes away with the patch when the plugin stops.

## When a patch crashes

A component patch that throws can't take Discord down with it. What renders depends on what threw:

| What threw | What renders | Does Discord's UI remount? | Counts toward removal? |
| --- | --- | --- | --- |
| An element you added next to Discord's | Nothing, in that element's place, until it unmounts | No | No, it's only logged |
| Your callback | Discord's tree as it was before your patch ran | Yes, if your patch changed its shape | Yes |
| Anything else in your tree | Discord's tree from the same render, until the component unmounts | Yes, below the component | Yes |

The first row is the one to aim for. When it applies, a focused chat input keeps its text and the keyboard stays open.

### Which elements count as added

An element counts as added when none of the elements Discord rendered are inside it. Your own component placed beside Discord's children, pushed into them, or put in a Fragment with them all count.

- Unbound wraps each added element in a small error boundary, keyed like the element, so its siblings keep their places.
- A parent that reads its children's props sees the boundary, not your element.
- An element with the same type as one of Discord's siblings stays unwrapped, because its parent may read it as one item of a list.
- A tree with none of Discord's elements in it replaced Discord's. The other two rows apply to it.
- An element that wraps Discord's, such as a provider around `result`, isn't isolated. If it throws, the last row applies.

Unbound records Discord's elements in a `WeakSet` before your callback runs, so it never keeps a tree alive. Each render of a patched component costs about 3 µs more.

### Falling back and removal

To fall back without running Discord's render twice, Unbound keeps a copy of Discord's tree from each render of a patch that has failed before. A patch that has never failed pays nothing for it. On a patch's first failure the component renders nothing for one frame, then re-renders with the copy.

Nothing is shown to the user for a single crash. Unbound only logs the error, naming the component, and the element when one you added crashed.

After 3 crashes in a row, Unbound removes the patch and shows a toast saying it was turned off. A render that commits cleanly resets the count. When several patches on one component built the tree that crashed, each of them counts the crash, since Unbound can't tell which one caused it. The patch stays removed until your plugin starts again.

Your patch's tree sits inside a small error boundary. Later `after` patches still get your tree as `result`, not the boundary. Text, `null` and other trees that can't throw aren't wrapped.

## Undoing a component patch

Unbound removes your patches when the plugin stops, and so does the function each patch returns. You don't need to re-render anything. Mounted components re-render with Discord's original render, and function components keep their state, even when your patch called hooks.

Your `stop` still undoes changes a callback made outside the render, such as a value it wrote onto a Discord object. Remove your patches first if `stop` also makes Discord draw again, as [How Plugins Run](/docs/developer/plugins/introduction#remove-your-own-patch-before-you-redraw) explains.

## Searching any tree

`utils.findInTree` searches any object, not only render results. It walks every key depth-first and returns the first value your function matches. `utils.filterInTree` returns every match.

```ts
import { utils } from '@unbound-app/api';

declare const state: unknown;

const channel = utils.findInTree(state, (node) => node?.type === 'GUILD_TEXT');
```

`utils.react.findInTree` and `utils.react.filterInTree` search React's own trees. They walk the keys elements and fibers keep their tree in (`props`, `children`, `type`, `child`, `sibling`, `memoizedProps`, `memoizedState` and `stateNode`), and only downward. Start from an element, a fiber, or a class instance's `_reactInternals`.

```ts
import { utils } from '@unbound-app/api';

declare const instance: { _reactInternals: unknown };

const fiber = utils.react.findInTree(
	instance._reactInternals,
	(node) => node?.memoizedProps?.channelId,
);
```

Every search takes options as its last argument:

| Option | Does |
| --- | --- |
| `walkable` | `utils.findInTree`: the only keys to walk. `utils.react`: keys to walk as well, such as `'return'` to go up a fiber tree |
| `ignore` | Keys never to walk |
| `maxDepth` | How many levels to walk below the start. Defaults to `100` |

Every search skips a value it has already seen, so a tree that points back at itself can't loop forever. See [utils](/docs/sdk/latest/utils) in the SDK reference.

<Tip>
	Patch the smallest component that does the job. A patch on a large component that renders often runs your code on every render.
</Tip>
