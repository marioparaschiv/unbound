A plugin that calls the native bridge tests it with the fakes of `native` from `@unbound-app/api/testing`. Read [Testing](/docs/developer/plugins/testing) first for the preset and `startPlugin`.

## Reference

| Call | Does |
| --- | --- |
| `native.setPlatform(platform)` | Sets the host platform, `'ios'` until set. `Platform.OS` from `react-native` follows it |
| `native.registerModule(name, module)` | Gives `getNativeModule(name)` a module to return |
| `native.setCapabilities(capabilities)` | Sets what `native.has` reports |
| `native.objc.registerClass(name, { superclass?, methods?, classMethods? })` | Adds a class. A method takes the object and the call's arguments; `callSuper` reaches the superclass's |
| `native.objc.create(name, ivars?)` | Makes an object, with the instance variables `getIvar` reads |
| `native.java.registerClass(name, { superclass?, methods?, staticMethods?, fields?, staticFields?, construct? })` | Adds a class. A method takes the object and the call's plain arguments, and returns a plain value, which the bridge tags as `string`, `int`, `double`, `boolean`, `null`, `handle` or `array`. `construct` runs for `java.construct` |
| `native.java.create(name, fields?)` | Makes an object, as a `handle` value |
| `native.calls` | Every `objc`, `java` and `hooks` call the plugin made this test: its `bridge`, `method`, `target` class, `name` (selector or method) and `args` |

## The platform and its modules

`native` follows the platform a test sets. It is iOS until `native.setPlatform` says otherwise, and `Platform.OS` from `react-native` follows it too.

```ts
import { native } from '@unbound-app/api/testing';

native.setPlatform('android');
native.registerModule('NativeFileModule', { readFile: async () => '' });
native.setCapabilities(['native.java.hooks']);
```

`definePlatform` picks the handler for that platform, and throws `NativePluginUnsupportedPlatformError` when there is none. A plugin calls it as it imports its `platform.ts`, before any test sets the platform, so a function handler comes back as a function that calls the current platform's handler each time it runs. Any other handler is read when `definePlatform` runs. `getNativeModule(...names)` returns the first module registered under one of the names. `native.has` reports the capabilities set.

`startPlugin` gives `context.native.objc` on iOS, and `context.native.java` and `hooks` on Android. Fill them with the classes your handlers reach:

```ts
import { native, startPlugin } from '@unbound-app/api/testing';

native.objc.registerClass('UIView', {
	superclass: 'NSObject',
	methods: { 'setAlpha:': (self, alpha) => {}, 'tag': () => 7 },
	classMethods: { sharedView: () => native.objc.create('UIView') },
});
await startPlugin();

native.setPlatform('android');
native.java.registerClass('android.view.View', {
	methods: { getWidth: () => 120 },
	fields: { mLeft: 4 },
	staticMethods: { create: () => native.java.create('android.view.View') },
	staticFields: { INSTANCE: native.java.create('android.view.View') },
});
```

`objc` fakes `getClass`, `alloc`, `create`, `className`, `respondsTo`, `call`, `invoke`, `invokeAsync`, `callSuper`, `invokeSuper`, `batch`, `prepare`, `invokePrepared`, `getIvar`, `setIvar`, the associated objects, `struct` and `hook`. `java` fakes `getClass`, `construct`, `describe`, `className`, `respondsTo`, `invoke`, `invokeAsync`, `getField`, `setField`, `batch`, `batchAsync`, `prepare`, `invokePrepared`, the associated objects and `release`, and `hooks` fakes `hook`, `remove` and the return values. A hook runs when a registered method is called, as `objc.hook`'s `before`, `replace` and `after` do. A class, selector, method or field a test did not register throws, naming how to add it. A member the kit does not fake throws too; give your own with `startPlugin({ native: { objc: { snapshot } } })`.
