A plugin can add its own slash commands. They show in Discord's `/` picker, in an **Unbound** section. When the user sends one, your plugin runs it on the phone, so it works in every channel and DM without a bot.

Every text the picker shows is a message key from your plugin's `i18n/en-US.json`, so the picker shows it in the user's language and falls back to en-US. See [Translations](/developer/plugins/i18n) for the `i18n/` folder.

## A first command

Add the text to `i18n/en-US.json`:

```json i18n/en-US.json
{
	"SHRUG_DESC": "Send a message with a shrug on the end",
	"SHRUG_MESSAGE_DESC": "What to say"
}
```

`commands.register` takes an object of commands, keyed by name:

```ts src/shrug/index.ts
import { commands } from '@unbound-app/api';

export function startShrug() {
	commands.register({
		shrug: {
			description: 'SHRUG_DESC',
			options: {
				message: commands.option.string({ description: 'SHRUG_MESSAGE_DESC', required: true }),
			},
			execute: ({ message }) => `${message} ¯\\_(ツ)_/¯`,
		},
	});
}
```

`description` takes a key of `i18n/en-US.json`, and TypeScript rejects anything else: literal text such as `'Send a shrug'` and a key the file lacks are both type errors. Command and option **names** stay literal, because Discord only accepts lowercase ASCII names.

`execute` gets the options the user filled in, already typed from `options`. Here `message` is a `string`, because the option is a required string. An optional option arrives as `undefined` when the user leaves it out.

Unbound removes your commands when the plugin stops. When the user changes Discord's language, the picker shows the new language's text.

## What a command can reply

What `execute` returns decides what happens next. It may also return a promise of any of these.

| Return | Result |
| --- | --- |
| A string | Sent to the channel as a normal message from the user |
| `{ content }` | The same, and `tts: true` sends it as text-to-speech |
| `{ ephemeral: true, content }` | Shown only to the user, as a bot message. Can add `embeds` |
| Nothing | Nothing is sent |

If `execute` throws, the user sees the error as an ephemeral message.

```ts
commands.register({
	'channel-id': {
		description: 'CHANNEL_ID_DESC',
		execute: (_options, { channel }) => ({ ephemeral: true, content: channel.id }),
	},
});
```

The second argument is the context: the `channel` the command was sent in, and its `guild`, which is `undefined` in DMs.

## Options

Each option is made with a builder on `commands.option`. Every builder takes a `description` key and `required`. Without a `description`, the picker shows the option's name.

| Builder | The handler gets | Extra settings |
| --- | --- | --- |
| `string()` | A string | `minLength`, `maxLength`, `autocomplete` |
| `integer()`, `number()` | A number | `minValue`, `maxValue`, `autocomplete` |
| `boolean()` | `true` or `false` | None |
| `user()`, `channel()`, `role()` | The picked user, channel or role | None |
| `choice({ ... })` | One of the map's values | None |

`choice` limits an option to fixed values. It takes a map from each value to the key of its label, and types the handler's value as the union of the map's values:

```json i18n/en-US.json
{
	"COIN_DESC": "Flip a coin",
	"COIN_CALL_DESC": "Heads or tails",
	"COIN_HEADS": "Heads",
	"COIN_TAILS": "Tails"
}
```

```ts
commands.register({
	coin: {
		description: 'COIN_DESC',
		options: {
			call: commands.option.choice(
				{ heads: 'COIN_HEADS', tails: 'COIN_TAILS' },
				{ description: 'COIN_CALL_DESC', required: true },
			),
		},
		// `call` is 'heads' | 'tails'.
		execute: ({ call }) => (Math.random() < 0.5 ? call : `Not ${call}`),
	},
});
```

The picker lists the choices in the map's order. The values are strings; for a number, use `integer()` or `number()` with `minValue` and `maxValue`.

Autocomplete suggestions are data, such as names, so their labels are plain strings, not keys.

## Grouping commands

Give a command `subcommands` instead of `execute` to group related commands under one name, such as `/notes add` and `/notes list`.

```ts
const notes: string[] = [];

commands.register({
	notes: {
		description: 'NOTES_DESC',
		subcommands: {
			add: {
				description: 'NOTES_ADD_DESC',
				options: { text: commands.option.string({ required: true }) },
				execute: ({ text }) => {
					notes.push(text);
				},
			},
			list: {
				description: 'NOTES_LIST_DESC',
				execute: () => ({ ephemeral: true, content: notes.join('\n') }),
			},
		},
	},
});
```

## Build errors

`ubd build` checks every `commands.register({ ... })` it can read and lists all problems at once, then exits with an error. `ubd dev` prints the same list and keeps the last good build on the device.

```text
Command text must be message keys from i18n/en-US.json (3 problems):
src/index.ts:3:23  /coin  description "Flip a coin" is literal text where a message key is required.  Fix: use its key "COIN_DESC".
src/index.ts:9:32  /coin  option "call" choice "edge" label key "COIN_EDGE" is missing from i18n/en-US.json.  Fix: add "COIN_EDGE": "<en-US text>" to i18n/en-US.json.
src/notes.ts:2:1  /notes  registers commands, but the plugin has no i18n/ folder.  Fix: add i18n/en-US.json with a key for each command description.
```

Each line gives the file, line and column, the command, the problem and its fix. The build reports:

- a key missing from `i18n/en-US.json`;
- literal text where a key is required;
- an en-US text longer than 100 characters;
- `option.choice` called with an array, the old form;
- a plugin that registers commands without an `i18n/` folder.

A tree the build cannot read, such as one built at runtime or a key from a variable, is checked when it registers.

## Limits

`register` checks every command and throws a `CommandDefinitionError` that names the command it rejected, and the key:

```text
Invalid command "/coin" from my-plugin: description "COIN_EDGE" is not a key in i18n/en-US.json. Use a key, and add it there.
```

- Names are 1 to 32 lowercase letters, digits, `-` or `_`.
- Every description and choice label is a key of `i18n/en-US.json`, whose en-US text is 1 to 100 characters.
- The labels of one `choice` differ in en-US.
- A command has at most 25 options, a group 1 to 25 subcommands, and a `choice` 1 to 25 values.
- A name another plugin already registered is taken.
