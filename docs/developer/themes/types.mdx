A theme's colors live in `bundle.json`: a base `type`, `semantic` roles and `raw` system colors.

<FileTree>
	<Folder name='my-theme'>
		<File name='manifest.json' note='See The Manifest' />
		<File name='bundle.json' note='Colors and background' />
	</Folder>
</FileTree>

<Warning>
	The file must be named `bundle.json`. Themes ignore the manifest's `main` field.
</Warning>

## Example

```json bundle.json
{
	"type": "darker",
	"raw": {
		"systemBlueColor": "#c74050"
	},
	"semantic": {
		"BACKGROUND_PRIMARY": { "type": "color", "value": "#0c0c0c" },
		"TEXT_NORMAL": { "type": "color", "value": "#fcfcfc", "opacity": 1 },
		"BUTTON_BACKGROUND": { "type": "raw", "value": "systemBlueColor" }
	},
	"background": {}
}
```

For `background`, see [Backgrounds](/docs/developer/themes/backgrounds).

## Base Type

`type` sets the palette your theme builds on. Anything you don't override falls back to it.

| `type` | Base palette |
| --- | --- |
| `light` | Light |
| `dark` | Ash, Discord's lightest dark theme |
| `darker` | Dark, deeper than Ash |
| `midnight` | Onyx, pure black for OLED screens |

## Semantic Colors

Each key is a Discord color role's selector name, such as `BACKGROUND_PRIMARY` or `TEXT_NORMAL`. Setting one recolors every place that role is used.

<ResponseField name='type' type="'color' | 'raw'">
	`color` is a literal value. `raw` points to a key in your `raw` map.
</ResponseField>
<ResponseField name='value' type='string'>
	The color, or the raw key when `type` is `raw`.
</ResponseField>
<ResponseField name='opacity' type='number'>
	Optional, `0` to `1`. Replaces any alpha in the color. Ignored when a `raw` entry names a key your `raw` map lacks.
</ResponseField>

- A key that matches no selector does nothing, with no warning.
- An entry missing `type` or `value` is skipped and keeps its original color.

## Raw Colors

`raw` is a flat map keyed by a system color's selector name, such as `systemBlueColor`. It replaces that color everywhere, below Discord's roles.

- Semantic entries with `"type": "raw"` share the raw value.
- Raw overrides apply with the theme and are restored when you switch themes.

<Tip>
	Put brand colors in `raw` and point semantic roles at them. One edit then recolors them all.
</Tip>

## Color Formats

Every color string, in `raw` or a semantic `color` entry, accepts:

| Format | Alpha |
| --- | --- |
| `#RRGGBB` | Opaque |
| `#RRGGBBAA` | Final byte, `00` to `FF` |
| `rgb(r, g, b)` | Opaque. Channels `0` to `255` |
| `rgba(r, g, b, a)` | `a` is `0` to `1`. Channels `0` to `255` |

<Warning>
	`rgba` alpha is a fraction. `rgba(255, 0, 0, 255)` is not opaque red; use `rgba(255, 0, 0, 1)`. A `0` alpha renders fully transparent, with no error.
</Warning>

These fail to parse:

- `rgba` with fewer than four values.
- `rgb` with fewer than three values.
- Anything not starting with `#`, `rgb` or `rgba`, including named colors like `red`.

<Note>
	A color that fails to parse shows no error. That entry keeps Discord's color. When a color doesn't change, check its format first.
</Note>
