This guide builds a small working plugin that finds a Discord module, patches it, and stores a setting.

Plugins have the most features of any addon kind, so they make the best example. Themes and icon packs use the same manifest and lifecycle, with different content.

<Steps>
	<Step title='Describe it with a manifest' icon='circle-info'>
		Create a `manifest.json` with at least the required fields. The [manifest](/addons/manifest) is the metadata Unbound uses to list, attribute, and validate your addon.

		```json manifest.json
		{
			"id": "hello-world",
			"name": "Hello World",
			"description": "Logs a greeting when a message is sent.",
			"authors": [{ "name": "you", "id": "1234567890" }],
			"version": "1.0.0",
			"main": "index.js"
		}
		```

		<Note>
			`main` points at your entry file. `id` is the name you use everywhere else. See [the manifest](/addons/manifest) for the full field list.
		</Note>
	</Step>

	<Step title='Write the entry point' icon='file-code'>
		Your `main` file default-exports an object with optional `start` and `stop` hooks.

		- Unbound calls `start` when the plugin is enabled. Set everything up here.
		- Unbound calls `stop` when the plugin is disabled. Undo everything `start` did.

		```ts index.ts
		export default {
			start() {
				// set up patches, listeners, subscriptions
			},
			stop() {
				// undo everything start() did
			},
		};
		```

		<Warning>
			Unbound evaluates your bundle at startup, even when the plugin is disabled. Keep top-level code cheap and do the real work inside `start`. See [how plugins are loaded](/plugins/introduction#how-plugins-are-loaded).
		</Warning>
	</Step>

	<Step title='Find what you want to change' icon='magnifying-glass'>
		Use [Metro](/modules/metro) to find the Discord module you need. Wrap the lookup in `utils.lazy` so the search only runs the first time a property on it is accessed.

		```ts
		import { metro, utils } from '@unbound-app/api';

		const Messages = utils.lazy(() =>
			metro.findByProps('sendMessage', 'receiveMessage'),
		);
		```
	</Step>

	<Step title='Patch it' icon='object-subtract'>
		Wrap the function with the [patcher](/modules/patcher). Create a patcher scoped to your plugin so you can revert all of its patches at once.

		```ts
		import { patcher } from '@unbound-app/api';

		const Patcher = patcher.createPatcher('hello-world');

		// inside start():
		Patcher.before(Messages, 'sendMessage', ({ args }) => {
			console.log('Sending message to channel', args[0]);
		});
		```
	</Step>

	<Step title='Remember a setting' icon='database'>
		Save configuration with [storage](/modules/storage). Create a store named after your plugin `id`, then read and write keys on it. Values persist across reloads with no extra work.

		```ts
		import { storage } from '@unbound-app/api';

		const settings = storage.getStore('hello-world');
		settings.set('greeting', 'Hello from Unbound');
		settings.get('greeting', 'Hi'); // default if unset
		```
	</Step>

	<Step title='Clean up in stop' icon='broom'>
		Revert everything when the plugin is disabled. A single `unpatchAll` call undoes every patch the patcher made.

		```ts
		stop() {
			Patcher.unpatchAll();
		}
		```

		<Warning>
			If you skip cleanup, your patches keep running after the plugin is disabled. Always clean up in `stop`. If you patched a component's render, also force a re-render. See [cleaning up](/plugins/react-patching#cleaning-up).
		</Warning>
	</Step>
</Steps>

### The full plugin

All the steps combined into one file:

```ts index.ts
import { metro, patcher, storage, utils } from '@unbound-app/api';

const Patcher = patcher.createPatcher('hello-world');
const settings = storage.getStore('hello-world');

const Messages = utils.lazy(() =>
	metro.findByProps('sendMessage', 'receiveMessage'),
);

export default {
	start() {
		Patcher.before(Messages, 'sendMessage', ({ args }) => {
			const greeting = settings.get('greeting', 'Hi');
			console.log(greeting, '→ channel', args[0]);
		});
	},
	stop() {
		Patcher.unpatchAll();
	},
};
```
