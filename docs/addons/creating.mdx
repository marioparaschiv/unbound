This guide builds a small working plugin that finds a Discord module, patches it, and stores a setting.

Plugins have the most features of any addon kind, so they make the best example. Themes and icon packs use the same manifest and lifecycle, with different content.

`ubd create` scaffolds a plugin in the standard layout. This guide builds one file by hand to show the API. Before you publish, follow the [authoring standards](/addons/standards).

<Steps>
	<Step title='Describe it with a manifest' icon='circle-info'>
		Create a `manifest.json` with at least the required fields. The [manifest](/addons/manifest) is the metadata Unbound uses to list, attribute, and validate your addon.

		```json manifest.json
		{
			"id": "hello-world",
			"name": "Hello World",
			"description": "Logs a greeting when a message is sent.",
			"authors": [{ "name": "you", "id": "1234567890" }],
			"version": "1.0.0",
			"main": "index.js"
		}
		```

		<Note>
			`main` points at your entry file. `id` is the name you use everywhere else. See [the manifest](/addons/manifest) for the full field list.
		</Note>
	</Step>

	<Step title='Write the entry point' icon='file-code'>
		Your `main` file default-exports an object with optional `start` and `stop` hooks.

		- Unbound calls `start` when the plugin is enabled. Set everything up here.
		- Unbound calls `stop` when the plugin is disabled. Undo anything Unbound can't undo for you.

		```ts index.ts
		export default {
			start() {
				// set up patches, listeners, commands
			},
		};
		```

		Your bundle runs with its own [Addon scope](/modules/introduction#the-addon-scope). Patches, commands, timers, and Metro, Flux and storage listeners made through it are removed when the plugin stops, so most plugins need no `stop`. The scope also gives you `addon`, your plugin's handle, and `logger`, which prefixes each line with your plugin's name.

		<Warning>
			Your bundle's top-level code runs each time the plugin starts, before `start`. Keep it cheap: no eager Metro searches. See [how plugins are loaded](/plugins/introduction#how-plugins-are-loaded).
		</Warning>
	</Step>

	<Step title='Find what you want to change' icon='magnifying-glass'>
		Use [Metro](/modules/metro) to find the Discord module you need. The `findBy*` helpers are lazy, so the search runs only the first time a property on the result is accessed. That makes them safe at the top of a file.

		```ts
		import { metro } from '@unbound-app/api';

		const Messages = metro.findByProps('sendMessage', 'receiveMessage');
		```
	</Step>

	<Step title='Patch it' icon='object-subtract'>
		Wrap the function with the [patcher](/modules/patcher). Your plugin's patches carry its `id`, and Unbound removes them when the plugin stops.

		```ts
		import { patcher } from '@unbound-app/api';

		// inside start():
		patcher.before(Messages, 'sendMessage', ({ args }) => {
			logger.log('Sending message to channel', args[0]);
		});
		```
	</Step>

	<Step title='Remember a setting' icon='database'>
		Save configuration with [storage](/modules/storage). `storage.getBucket()` returns your plugin's own Bucket, named after its `id`. Values persist across reloads with no extra work.

		```ts
		import { storage } from '@unbound-app/api';

		const settings = storage.getBucket();
		settings.set('greeting', 'Hello from Unbound');
		settings.get('greeting', 'Hi'); // default if unset
		```
	</Step>

	<Step title='Clean up what the scope cannot see' icon='broom'>
		If you patched a component's render, call `patcher.unpatchAll()` in `stop` and force a re-render, so the original UI comes back. See [cleaning up](/plugins/react-patching#cleaning-up).

		<Warning>
			The scope only removes what went through it. A listener you add straight to a Discord module, or a settings section you register, stays until your `stop` removes it.
		</Warning>
	</Step>
</Steps>

### The full plugin

All the steps combined into one file:

```ts index.ts
import { metro, patcher, storage } from '@unbound-app/api';

const settings = storage.getBucket();
const Messages = metro.findByProps('sendMessage', 'receiveMessage');

export default {
	start() {
		patcher.before(Messages, 'sendMessage', ({ args }) => {
			const greeting = settings.get('greeting', 'Hi');
			logger.log(greeting, '→ channel', args[0]);
		});
	},
};
```
