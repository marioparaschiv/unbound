The iOS loader keeps all of Unbound's files in a single `Unbound` folder in the app's Documents directory.

### Storage

To browse the folder in the Files app, open `On My iPhone` -> `<App Name>` -> `Unbound`.

<AccordionGroup>
	<Accordion title='Addons' icon='puzzle-piece'>
		Each addon type has its own directory:

		| Directory | Contents |
		| --- | --- |
		| `Plugins/<id>` | An installed [plugin](/addons/introduction): its `manifest.json` and bundle, in a folder named after the plugin's id. |
		| `Themes/<id>` | An installed [theme](/themes/introduction): its `manifest.json` and bundle, in a folder named after the theme's id. |
		| `Fonts` | Installed font files, stored directly in this folder with no subfolders. |
		| `Icons/<id>` | An installed icon pack, in a folder named after the pack's id. Its images follow the same layout as Discord's asset tree. |

		To remove an addon, delete its folder. The loader scans these directories at startup, so changes take effect only after the app restarts.

		The toolbox's **Wipe Plugins**, **Wipe Themes**, **Wipe Fonts**, and **Wipe Icon Packs** actions each permanently delete the matching directory. **Factory Reset** deletes the entire `Unbound` folder, including `settings.json` and the bundle.
	</Accordion>
	<Accordion title='Settings' icon='gear'>
		`settings.json` holds every Unbound setting, including the [loader configuration flags](/loader/configuration) and everything in the [settings reference](/loader/settings).

		If this file can't be read or isn't valid JSON, the loader copies it to `settings.json.corrupt-<timestamp>` and starts with a fresh file instead of refusing to boot. If your settings disappear unexpectedly, look for that backup.
	</Accordion>
	<Accordion title='Bundle' icon='box'>
		`unbound.bundle` (or `unbound.js`, depending on the source you point at) is the JavaScript bundle the loader injects. Don't manage it by hand. Use the toolbox's bundle actions instead. **Delete Bundle** deletes this file and also clears `loader.update.url` and `loader.update.force`.
	</Accordion>
</AccordionGroup>

<Note>
	Icon packs are stored in `Icons`, even though the toolbox's wipe action is labelled "Wipe Icon Packs".
</Note>

For the toolbox, recovery mode, and bug reports, see [Troubleshooting](/user-guide/troubleshooting).
