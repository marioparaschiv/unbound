### What is Flux?

Flux is how Discord manages its state. A central dispatcher broadcasts actions, such as a message arriving, a channel being selected, or the user's settings changing. Stores listen for those actions and hold the resulting state.

- To get *what* Discord currently knows (the current user, a guild, the selected channel), read a store.
- To run code *when* something happens, subscribe to the dispatcher.

Both come from [Metro](/modules/metro). Find stores with `findStore`. The dispatcher and common stores are already resolved on `metro.common` and `metro.stores`.

### Reading stores

A store is a singleton with getters for Discord's state. Find it once, lazily so the search doesn't run at import, then read from it whenever you need to.

```ts
import { metro, utils } from '@unbound-app/api';

const UserStore = utils.lazy(() => metro.findStore('User'));

// later, inside start() or a handler:
const me = UserStore.getCurrentUser();
```

<Tip>
	The most commonly used stores (`Users`, `Guilds`, `Theme`) are already resolved on `metro.stores`, so you don't need to search for them.
</Tip>

### Subscribing to events

The dispatcher emits typed actions. Subscribe to an action type to run code each time Discord dispatches it, and unsubscribe when your plugin stops.

```ts
import { metro } from '@unbound-app/api';

export default {
	start() {
		this.handler = ({ channelId }) => {
			console.log('Channel selected:', channelId);
		};

		metro.common.Dispatcher.subscribe('CHANNEL_SELECT', this.handler);
	},
	stop() {
		metro.common.Dispatcher.unsubscribe('CHANNEL_SELECT', this.handler);
	},
};
```

<Warning>
	Always `unsubscribe` in `stop`, passing the *same* handler reference you subscribed with. A subscription that outlives a disabled plugin keeps firing, so your plugin's code keeps running after the plugin is turned off.
</Warning>

### Common action types

Discord dispatches hundreds of action types. These are some you'll see often:

<AccordionGroup>
	<Accordion title='Messages' icon='message'>
		`MESSAGE_CREATE`, `MESSAGE_UPDATE`, `MESSAGE_DELETE`, fired when messages are sent, edited, or deleted.
	</Accordion>
	<Accordion title='Navigation' icon='compass'>
		`CHANNEL_SELECT`, `GUILD_SELECT`, fired when the user switches channels or servers.
	</Accordion>
	<Accordion title='Connection' icon='wifi'>
		`CONNECTION_OPEN`, fired once the client is connected and stores are populated. Use it for setup that needs live state.
	</Accordion>
</AccordionGroup>
